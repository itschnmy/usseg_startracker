# Branch audit and integration decisions

Audit date: 2026-08-24. Integration branch: `integration/unified-startracker-eval`, based on
`origin/attitudeEstimator` (`bfc5893`). The feature branches diverge near the start of the project,
so merging all branch tips would combine duplicate experiments and large generated artifacts.
The integration therefore selects modules by responsibility.

| Remote branch | Useful implementation | Integration decision |
|---|---|---|
| `main` | Python image detector and Tetra plate solver; 10–30° Tetra database | Selected detector and solver |
| `StarDetector` | Early C++ OpenCV detector and bundled Eigen | Superseded by the newer copy on the base branch |
| `attitudeEstimator` | Newest C++ detector/voting/QUEST and Python TRIAD, QUEST, Davenport, SVD, MEKF | Used as integration base |
| `kvector` | Python pair-angle/k-vector experiment | Kept as reference; it rebuilds its database at runtime |
| `tetra` | Earlier Tetra plus attitude-control experiment | Superseded by the newer Tetra copy from `main` |
| `test` | OpenMV/hardware experiments | Kept separate because it targets a different runtime |

The unified production path is:

`grayscale image -> threshold/centroid detector -> Tetra star ID -> matched vectors -> SVD Wahba attitude`

The C++ voting path is retained and tested, but is not used for bulk lost-in-space evaluation yet.
Its recursive candidate search needs a bounded runtime policy before it can safely process noisy images.

## Database provenance

The database committed on `main` is 49,414,085 bytes and declares a supported FOV range of
10–30°. It is materialized from Git instead of duplicated in the integration diff. A separate 45°
database is generated by `scripts/generate_tetra_database.py` from the complete 118,218-row CDS
Hipparcos catalogue. The 5,729-row `hip_main.dat` stored on the historical branch is explicitly
rejected by the generator because it produced an incomplete all-sky database.

## Quaternion convention

The repository's estimators return passive inertial-to-body quaternions. LOST eval fixtures store
the inverse body-to-inertial rotation. The pipeline emits both values explicitly and exposes the
LOST-compatible value as `quaternion_wxyz`; comparing the unconverted values produces a large but
spurious attitude error.
