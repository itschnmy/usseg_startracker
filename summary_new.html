Attitude Solvers Comparison

★ TRIAD Estimator

Calculates attitude deterministically using exactly two vector observations. Constructs orthogonal reference matrices from cross products.

  • Input limits: Exactly 2 vector pairs
  • Complexity: Extremely low ($O(1)$)
  • Output: Active rotation (Body → Inertial)
  • Use Case: Safe/degraded pointing fallback
$$\mathbf{Q} = \mathbf{T}_n \mathbf{T}_b^T$$

★ QUEST Estimator

Solves Wahba's problem using Shuster's quartic characterization. Newton-Raphson estimates largest eigenvalue to compute the Gibbs vector.

  • Input limits: ≥ 3 vector pairs (fallback to TRIAD if 2)
  • Complexity: Low-medium (Newton-Raphson)
  • Output: Passive rotation (Inertial → Body)
  • Use Case: Primary onboard attitude determination
$$\det((\lambda + \sigma)\mathbf{I} - \mathbf{S}) = 0$$

★ Davenport Q Estimator

Optimal solver resolving the Davenport K-matrix eigenvalues. Reconstructs attitude from the maximum eigenvalue's corresponding eigenvector.

  • Input limits: ≥ 3 vector pairs (fallback to TRIAD if 2)
  • Complexity: High (eigenvalue solver)
  • Output: Passive rotation (Inertial → Body)
  • Use Case: Redundant cross-validation solver
$$\mathbf{K} \mathbf{q} = \lambda_{\max} \mathbf{q}$$

★ MEKF Estimator

Recursive 6-state Extended Kalman Filter fusing low-frequency star tracker vectors with high-frequency gyroscope rate sensors.

  • Input limits: Gyro rate + observation vectors
  • Complexity: Medium-High (time propagation)
  • Output: Passive rotation & Gyro Bias estimation
  • Use Case: Dynamic spacecraft tracking & mission mode
$$\mathbf{q}_{k+1} = \mathbf{q}_k \otimes \delta\mathbf{q}(\delta\theta_k)$$

Codebase Deep-Dive: Frame Conventions

⚠️ Convention Conflict: Active vs. Passive Rotation
Analysis of the C++ codebase revealed a critical inconsistency in the returned attitude representations:
1. TRIAD Solver: Computes the rotation matrix $Q = T_n T_b^T$. This maps body-frame vectors directly to the inertial frame, representing the active rotation ($B \rightarrow N$).
2. QUEST Solver: Minimizes the Wahba gain function. The resulting quaternion represents the rotation mapping reference inertial vectors to body-frame observations, representing the passive rotation ($N \rightarrow B$, the transpose of TRIAD).

Resolution: The Python package maintains absolute fidelity to this convention mismatch to ensure it can act as a drop-in replacement. The verification test script validates both TRIAD (against active quaternion) and QUEST/Davenport (against passive conjugate quaternion) with 100% mathematical accuracy.

Mathematical Verification Logs

The validation script has been updated to verify all solvers (TRIAD, QUEST, Davenport Q) and the recursive MEKF filter. Rather than random vectors, it verifies them using real star catalog coordinates and simulated dynamic sensor readings.

📊 Verification Dataset

  • Static Solvers: 5 real stars of the Crux constellation loaded from star_catalog.csv.
  • MEKF Simulation: 10-second dynamic trajectory at 100Hz with 5Hz Star Tracker updates. Gyro rate sensor measurements include rate noise and constant bias drift ($[0.005, -0.003, 0.002]$ rad/s).

🎯 Success Conditions

  • TRIAD / Davenport Q: Angular error ≤ $10^{-7}$ degrees.
  • QUEST: Angular error ≤ $10^{-5}$ degrees.
  • MEKF Filter: Final attitude convergence error ≤ $0.1$ degrees, and final gyro rate bias convergence error ≤ $0.0015$ rad/s.

🧮 Correctness Formulas

Attitude Error (Deg):
$$\theta_{err} = 2 \arccos(|q_{true} \cdot q_{est}|) \times \frac{180}{\pi}$$
Gyro Bias Error (rad/s):
$$\beta_{err} = \|\beta_{true} - \beta_{est}\|_2$$

📋 Hướng Dẫn Kiểm Tra Thủ Công (Manual Verification Steps)

Bạn có thể kiểm chứng tính đúng đắn của kết quả tính toán trên CubeSat một cách thủ công thông qua 4 bước đơn giản sau:
  1. Chạy kiểm thử: Mở Terminal tại thư mục usseg_startracker/ và thực thi lệnh: uv run python test/test_attitude_determinator.py
  2. Đối chiếu chéo (Cross-Check): Quan sát dòng QUEST Estimated Quaternion và Davenport Q Estimated. Do cả hai bộ giải này đều nhận chung đầu vào 5 ngôi sao chòm Crux và giải cùng một bài toán tối ưu hóa Wahba, giá trị Quaternion của chúng phải giống hệt nhau (ít nhất là 5 chữ số đầu sau dấu phẩy).
  3. Kiểm tra chuẩn hóa Quaternion (Unit Norm Check): Chọn một Quaternion ước lượng bất kỳ $[q_w, q_x, q_y, q_z]$ trong log kết quả, tính độ dài của nó:
    ||q|| = sqrt(q_w² + q_x² + q_y² + q_z²)
    Kết quả tính ra bắt buộc phải luôn bằng 1.0 (cho phép sai số làm tròn số thực dấu phẩy động ở mức cực nhỏ $\sim 10^{-15}$).
  4. Xác nhận độ hội tụ của bộ lọc MEKF: Ở cuối bảng log, hãy kiểm tra xem giá trị Final Attitude Error đã giảm sâu xuống dưới $0.1^\circ$ (thường đạt $\approx 0.04^\circ$) và sai số bias Final Gyro Bias Error đã nhỏ hơn $0.0015$ rad/s (thường đạt $\approx 0.0004$ rad/s) hay chưa. Nếu thỏa mãn, bộ lọc Kalman đang hoạt động cực kỳ ổn định.
